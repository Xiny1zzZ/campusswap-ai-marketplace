BUILDING CAMPUSSWAP

My project notes

What I built, how I approached the project, how the AI works, and what is intentionally left out of this demo.

What I built and who it is for

CampusSwap is an AI-enabled second-hand marketplace demo built for students who want an easier way to find affordable items for campus life. I built it as part of the CognitioLabs Associate Forward Deployed Engineer assessment.

The marketplace includes a responsive catalogue, individual listing pages, category filtering, semantic search, and an Ask AI feature. Users can search by item name or simply describe what they need. They can also ask questions about the catalogue, compare listings, and open relevant items directly from the AI response.

Navigation between browse results, listing pages, and Ask AI is designed to preserve useful page state where possible, so users can move around the demo without constantly starting over.

How I approached the build

I started by breaking the assessment into a few core goals: build a public, mobile-friendly second-hand marketplace, let users find items using natural language, and provide an AI that can answer questions using the catalogue. Instead of trying to build a complete marketplace immediately, I focused first on the main reviewer journey: browse items, search, open a listing, and ask the AI about the catalogue.

I first built the basic catalogue, category filtering, and listing pages. When I moved on to search, I considered simple keyword matching, but realised it would be limited when someone describes a need instead of typing an exact item name. For example, a student might search for "something cheap for studying". I therefore added embeddings so the search can use semantic meaning. I later simplified this into one search box because users should not need to understand or choose between technical search modes.

After search was working, I designed Ask AI to solve a different problem. Search helps users find items, while Ask AI helps them understand and compare items in the catalogue. I also considered the risk of the model inventing information, so I designed the Q&A flow to ground answers in the seeded catalogue and to acknowledge when information such as warranty, delivery, or availability is not provided. Because the demo has only 36 listings, I chose to use the full compact catalogue as grounding context rather than relying only on a few Top-K search results.

Finally, I went through the site again from the point of view of a normal user and a reviewer. This led me to improve navigation, preserve useful browse and Ask AI state, make the AI feature easier to discover, and test the responsive layout on desktop and mobile. I intentionally left out larger features such as login, payments, and seller messaging so I could keep the project focused on the assessment's main marketplace, AI, grounding, testing, and deployment requirements.

What is demo data

All 36 listings are fictional, seeded examples created for this assessment. They cover categories such as study, electronics, furniture, sports, lifestyle, room essentials, books, and clothing.

Item names, prices, conditions, sellers, and Singapore pickup locations are example data and are not real offers from students. The item images are emoji placeholders. No real purchase, reservation, payment, or seller conversation takes place in this demo.

Tools and AI

I used Codex as an AI coding tool to help inspect the repository, plan parts of the implementation, write and review code, and improve the project documentation.

The marketplace search uses openai/text-embedding-3-small through the CognitioLabs gateway. This allows users to search using natural language instead of relying only on exact keywords.

Ask AI uses the same embedding model to help order relevant catalogue records, then uses gpt-5.6-terra through the CognitioLabs OpenAI-compatible gateway to generate the final answer. The gateway key is read from the server-side CLASSGW_KEY environment variable and is not exposed to the browser.

How I keep the AI grounded

Ask AI is designed to answer using the seeded CampusSwap catalogue rather than general knowledge. Because this demo only has 36 listings, I provide the model with compact catalogue information for all of them after using embeddings to relevance-order the records.

This was an intentional choice. Using only a small Top-K set could leave out an item that matters for questions about things such as price, condition, or pickup location.

The model can suggest listing IDs in its response, but I do not trust those IDs directly. The backend validates them against the grounded catalogue and reloads the actual listing data from SQLite before sending clickable cards to the browser.

The AI is also instructed to say when the catalogue does not contain the information needed to answer a question, such as warranty, delivery, or availability, instead of inventing an answer.

What I intentionally left out

I kept the project focused on the assessment requirements rather than trying to build a complete production marketplace. I did not add user accounts, authentication, payments, seller messaging, listing management, image uploads, persistent chat history, or real transactions.

I also kept the technical setup intentionally small. The frontend uses Vue 3 directly in the browser without Vite or an npm build step, and the application uses SQLite rather than adding a separate vector database.

What I tested

The automated Python tests use a temporary SQLite database and mock external embedding and chat-completion calls, so the test suite does not consume real gateway requests. The tests cover catalogue seeding, filters, validation, semantic search behaviour, embedding caching, Q&A context construction, missing-fact responses, and safe failure behaviour.

I have also tested the deployed website in a desktop browser and on a mobile phone, including the main catalogue and responsive layout. A full accessibility and assistive-technology review has not been completed.

Known issues and limitations

CampusSwap is a deployed assessment demo, not a production marketplace. There is no identity or campus verification, moderation, stock tracking, payment flow, or real seller contact. SQLite is suitable for this small demo, but the current architecture is not designed for multiple application servers or production-scale marketplace traffic.

Semantic search and Ask AI depend on access to the CognitioLabs gateway. The current semantic search uses a 0.30 starting similarity threshold and returns at most five listings. These choices were tested for the small seeded catalogue and would need to be reviewed if the catalogue became much larger.

Ask AI uses grounding instructions and backend validation, but I have not completed a full adversarial-prompt evaluation. The demo also does not include pagination or sorting controls.
